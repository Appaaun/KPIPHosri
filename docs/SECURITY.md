# Security

Threats include department ID tampering, stolen sessions, privilege escalation, duplicate approvals, unsafe CSV content, password guessing, and malicious source queries. Server-derived scope and role checks are required for every resource operation. Zod validates mutation inputs; Prisma parameterizes queries. CSRF protection uses NextAuth's tokens for login/logout and an exact APP_URL Origin check on all application mutations. Do not enable wildcard CORS.

Passwords use Argon2id. Sessions expire in eight hours, are HTTP-only and SameSite Lax, and Secure in production. A current database lookup prevents use after disabling a user/department or changing role/password. Login attempts use a shared PostgreSQL account-keyed 10-attempt/15-minute budget. Add a trusted reverse-proxy IP limit and operational unlock policy at deployment; account-based throttling alone permits deliberate lockout. Unknown accounts still perform Argon2 verification. Generic login errors do not distinguish disabled accounts.

No credential values, hashes, or tokens are returned by the API or logged in audits. Source administration stores only safe metadata. CSV preview performs no writes; confirmation revalidates and writes atomically. Export escapes quotes and spreadsheet formula prefixes. Upload/JSON limits are enforced by a 300 KB streaming body ceiling, reverse proxy and route constraints. NextAuth credentials are also length-limited; retain the proxy upload cap for authentication routes.

Audit records are append-only via UPDATE/DELETE/TRUNCATE triggers. Audited writes share the application transaction. Database owners can bypass protections; use separate restricted runtime and migration credentials, TLS database transport when remote, encrypted disks/backups, and controlled administrator access. The current Compose bootstrap DB account owns schema for local convenience; split roles before production.

Security headers include frame denial, nosniff, same-origin referrer, and a CSP. Inline scripts/styles are allowed for Next/React compatibility; stronger nonce-based CSP is a hardening follow-up. This system has no analytics, external AI calls or patient-level model. Do not add clinical identifiers to notes. Restrict intranet access, run HTTPS, disable demo seeding, rotate secrets, review dependency advisories and commission security/load testing before production. See deployment and backup documents.

Dependency review: CSV parsing uses csv-parse 7.0.3. Prisma CLI's transitive deepmerge-ts is pinned through an override to patched 8.0.2; generation and migration deployment are tested with this override. Recheck advisories and this compatibility whenever upgrading Prisma. The runtime image currently includes migration/TypeScript tooling so the same image can run migrations and the worker; a hardened deployment can split purpose-specific images after testing.
