# Operations

Use `/admin/system` for database/web state, worker heartbeat and source run history. `/api/health` is the minimal unauthenticated container probe. Dashboard polling defaults to 45 seconds (configurable, clamped 30–300); it does not imply second-level source updates. Worker heartbeat runs every minute; WORKER_CRON controls processing ticks. Each enabled source has a separate UTC five-field cron and stale threshold. Choose a global worker tick at least as frequent as source schedules. Invalid source schedules are rejected. Worker concurrency is guarded locally and by a database advisory source lock. Multiple worker replicas are unnecessary for V1.

MOCK and HIMPRO adapter kinds are recognized; HIMPRO safely reports failure until a reviewed implementation exists. Other kinds remain manual/unsupported and must not be enabled for automated processing. Sync failures and stale-source alerts are distinct from RED KPI performance. Alerts are in-app, require scoped access, and can be resolved by authorized managers. A notifier contract exists for future channels; no external notifications are sent.

Use `/admin/audit` for safe immutable action metadata. Login attempt records are account-hash keys; arrange retention/cleanup per hospital policy for audit/sync/attempt history. Current list views cap recent records as documented in README. Monitor database size, disk capacity, backup success and worker heartbeat outside the application. Disable an account or reset password to revoke sessions. Department deactivation blocks its scoped users. Error logs intentionally contain error types, not payloads; use request/audit metadata for diagnosis.

## Cloud onboarding verification
The selected cloud machine uses Docker's `vfs` storage driver, so image builds and initial container filesystem creation can take substantially longer than on a typical overlay-based Ubuntu Docker host. Prefer the documented host Node development workflow with Compose PostgreSQL during development. The optional cloud image helper preserves TLS and artifact checksums.

For final container verification, the host and image lockfiles, Prisma schema, and exact Node version were compared before mounting the current production `.next` output read-only into the already verified dependency image. This avoids rebuilding unchanged dependencies. The temporary Compose override is a local verification aid, not part of normal deployment. Use `docker compose up --build -d` to produce images from the final repository source for deployment. Choose either host web/worker processes or Compose web/worker services; stop `web` and `worker` before switching to host development, while preserving PostgreSQL and its volume.
